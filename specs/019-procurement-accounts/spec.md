# 019 采购共享账户与预算

2026-11-01，**已实现 / 限定本地验收通过**。实施以[冻结合同](contract.md)为准，讨论稿仅保留早期取舍。本编号承接018成本报价和成本路由，提供供应商共享账户、累计采购预算及人工余额证据观察；证据与未实现边界见[验收记录](../../docs/verification/procurement-accounts.md)。

## 目标与不变量

1. 显式采购账户为多个渠道/credential共享额度主体，账户归属与客户租户独立；不可把多Key当多份余额。绑定版本化，attempt冻结账户与绑定身份，重绑定不重写历史。
2. 本地累计采购预算以数据库原子预占保证本库控制范围；每次supplier attempt独立预占，客户request仍只冻结一次。价格、计量硬界或账户身份未知时受控模式拒绝，不以0或客户售价代替。
3. 已发未知消费保留采购占用并独立对账。客户24小时释放、免收及退款不能释放潜在供应商消费；恢复只核查，不重发生成。
4. 账户暂停/预算收紧/绑定变更以锁内sending检查为生效屏障；已发attempt继续证据、结算、差额释放和对账。共用资金收尾不得加入新准入门禁。
5. 成本更正追加且幂等，不改旧快照；供应商退款须有证据，客户退款不代表供应商退款。
6. 余额查询是带来源、币种、供应商时刻、观察时刻、语义和新鲜度的观测，unknown不当0，不覆盖本地预算或held。供应商不支持查询时明确显示不支持。
7. API金额/revision用规范字符串；资金命令有持久ID与只读回执，未知写禁止换ID重放；客户接口不泄露采购账户、成本或秘密。

## 实施前必须冻结

- credential/channel版本与账户绑定的CAS边界，未绑定旧配置迁移和关闭控制语义。
- 累计预算的事件/余额关系、范围、超界异常入账及审批；周期预算若未实现须继续planned。
- attempt预占、sending、unknown、收尾与更正的完整状态机，崩溃窗口和长期unknown处置权限。
- 实际代码全部资金/配置路径的统一锁序，账户跨租户并发与多账户排序。
- 建议表/API/权限、不可变约束、受限角色、恢复及证据索引。

首阶段不含多币种/汇率、自动供应商充值、外部余额强一致保证、复杂阶梯价或法定会计总账。余额观察可后于本地预算实施；不得为接入查询而耦合018。
