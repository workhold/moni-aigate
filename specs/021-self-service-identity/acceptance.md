# 021 验收清单

2026-11-01，**已实现 / 限定本地验收通过**。勾选表示源码审查、自动化和隔离集成的本地范围，非所有浏览器操作或外部投递认证；逐项证据与限制见[021验证记录](../../docs/verification/self-service-identity.md)。

## 配置、接口与隐私

- [x] 默认注册关闭、邮件 transport 关闭；未配置邮件时两类邮件能力不可用，保留原登录；显式 SMTP 模式配置缺失/不安全则启动失败。
- [x] 非恢复模式、注册flag开启且邮件配置有效时，空库显示 setup_required 且不能先创建普通 user；Bootstrap 与初始化标志原子提交；既有 admin 库兼容回填，普通 user 不能伪造初始化。
- [x] 能力查询仅暴露有效能力和全站原因，不返回 SMTP 主机、凭据、收件地址、投递状态或任何邮箱存在信息。
- [x] 所有匿名 mutation 执行实例 guard、同源检查、恢复模式限制、严格大小/字段校验及有界 IP/邮箱/令牌限流。
- [x] 配置在排空/重启后生效；关闭暂停且不自动撤销，重新开启仅允许 TTL 内仍有效的旧证明，已过期/改密/替换证明不能复活；已进入 SMTP 的邮件不能撤回。
- [x] 存在/不存在/停用/已注册邮箱请求邮件的 HTTP 状态、JSON 正文和 `request_id` 格式相同；邮箱级冷却/上限静默返回同一 202；IP 429 不依赖账号存在与 MFA。
- [x] 审计、遥测、SMTP 错误、访问日志、浏览器 URL/存储中不保留原始令牌、密码、MFA 代码或邮件 payload；跨记录交换密文不能解密。

## 注册

- [x] 邮件证明前没有可登录账号；请求邮件不接收或保存密码；GET 邮件链接、预取和刷新均不消费证明。
- [x] 注册完成校验用途、摘要、当前 DB 时间、最新有效证明和邮箱；插入/唯一冲突等待后重验 TTL；过期、撤销、重复、跨用途、非法 token 同一失败契约。
- [x] 同一邮箱并发注册、与平台建用户/建租户/加成员并发最多创建一个用户；冲突不能覆盖密码、添加已有用户到新租户或接管既有租户。
- [x] 成功用户为 `none`，新租户普通 owner，`allow_all_models=false`，无模型 grants、API Key、现金/赠额/采购权益；正常登录后有明确无权益状态。
- [x] 用户、租户、成员、令牌消费及审计任一写失败全部回滚；提交结果不明时页面只提示核查/登录，不自动创建第二个账号。

## 密码恢复、MFA 与会话

- [x] 普通邮箱证明可更改未开启 MFA 用户密码；当前启用 MFA 的用户缺码/错码/旧 TOTP/已使用恢复码均不改密、不消费令牌、不撤销会话。
- [x] 正确 TOTP 或未用恢复码与重置在同一事务提交；并发使用同一令牌或恢复码最多成功一次。
- [x] 请求邮件后开启 MFA，重置必须读取新状态；关闭部署级强制 MFA 不跳过用户已启用 MFA。丢失全部因素不走邮件旁路。
- [x] 重置与 Login/ChangePassword/SetupMFA/VerifyMFA/Reauthenticate/Switch/Logout 的竞态和锁等待符合合同；拿锁后重新检查账号状态、证明 TTL、密码版本和当前 MFA；family 锁等待越过 TTL 时恢复码/TOTP 变更一起回滚。
- [x] 成功重置更换密码、递增密码版本、消费当前/撤销同主体其他证明、撤销全部 session families、记录审计原子提交；旧密码及全部旧会话失效，不自动签发新会话。
- [x] 一般改密使先前重置令牌失效；旧账号不因新增验证字段被禁止登录；成功恢复可记录邮箱验证时间。
- [x] API Key 维持独立状态；验收证明重置未暗中重发/撤销 Key，页面清楚显示这项边界。
- [x] 重置提交后使用旧 session family 发起的后续认证失败；已在此前通过认证的普通业务请求沿原行为完成，不把它们仍可提交误报成“所有在途敏感写均被撤回”。

## 邮件恢复与 SMTP

- [x] 请求事务只落库，不同步调用 SMTP；令牌与 outbox 同事务，payload 加密；TLS 校验证书/主机，禁用 TLS 降级，明文模式只接受 literal loopback fixture。
- [x] 真实PG中模拟claim提交后进程丢失、SMTP接受后ACK丢失、租约过期、旧代际ACK与恢复；结合worker的发送前/中失败和真实main正常排空，验证状态按合同推进，旧worker不能覆盖新claim。
- [ ] 指定claim后及SMTP接受/ACK前窗口的真实进程强制终止与重启故障注入尚未执行，纳入025生产故障验证；不能将上述PG状态模拟称为实际杀进程证据。
- [x] 单次只按空闲槽最多 claim 2 条，发送前复查 state/generation/剩余 lease，无预 claim 长队列；JOIN claim 明确只锁 outbox，清理保持 subject→challenge→outbox。
- [x] 同一 outbox 重试使用同一 message ID 和令牌；不创造第二个身份令牌或模型请求。SMTP 不确定窗口允许重复邮件，身份变更仍只发生一次。
- [x] 失效/过期令牌停止后续发送；替换与发送竞态可能出现旧邮件，但旧证明始终不能消费。失败不会把 sent 标成真实收件成功。
- [x] 5 次有界尝试、退避、租约和清理按合同执行；第 5 次 claim 后无 ACK 不永久悬挂，过租约转 dead 并清密文；dead 不冒充确定未投递。不可用密钥、SMTP 永久失败与临时失败只保留安全错误码。
- [x] 新密文离线重包保留 token/收件人/purpose/id，普通业务角色不能使用维护例外篡改内容；AUTH_SECRET 轮换使旧 proof 失效的边界清楚记录。
- [x] Guard 失效/恢复模式/正常退出停止新 claim 和发送；SMTP IO 有界可取消，事务不持有网络等待；两实例 fixture 的重复 claim 测试不冒充 HA 认证。

## 前端、集成与外部门禁

- [x] 邮件 fragment 在创建Router/history之前一次捕获并从URL及history.state清除，后续导航不复现；未确认不 POST；不写 localStorage/sessionStorage，不加载第三方资源；关闭/账号变化/页面切换的晚回隔离。
- [x] 邮件统一提示区分“请求已接受”与“已确认投递”；令牌过期、MFA 提示、重置后重新登录和提交结果不明都可理解。
- [x] 随机隔离 PostgreSQL、独立受限角色、本地 SMTP、真实程序浏览器链路和资源清理有证据；未操作预览真实账号、MFA 或客户资金。
- [x] 相关 race/vet、前端 strict、最终集成检查和统一架构复核齐全；真实 SMTP 验证域名/收件、投递信誉、生产反滥用仍独立待外部验证。

本切片不运行性能对标；022 支付、023 订阅/周期预算、024 媒体、025 HA 均保留独立 SDD 与验收，不能从本地邮件成功推导这些能力已完成。
