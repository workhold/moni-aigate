# 021 自助注册、邮箱证明与密码恢复

2026-11-01，**已实现 / 限定本地验收通过**。本切片承接账号、会话与可选 MFA，补齐对外运营所需的自助开户和邮箱恢复。接口、状态与锁序见[合同](contract.md)，模块设计见[详细设计](../../docs/design/self-service-identity.md)。

## 目标

1. 开放注册默认关闭。部署者配置邮件且合法完成平台初始化后才可能开放；空库不能由公开注册抢先创建普通 user 并封死管理员 Bootstrap。未配置邮件时，控制台明确显示能力不可用，不显示“邮件已发送”。
2. 注册先证明邮箱，再提交密码和租户名称；证明完成前不创建可登录用户。邮箱链接不能直接执行注册或重置。
3. 邮件令牌高熵、短期、单次使用、限定用途；数据库只保存摘要。持久邮件 outbox 内的投递材料加密，退出/崩溃后能恢复投递。
4. 新开户只创建 `platform_role=none` 的普通用户及其新租户 owner。余额为零，无模型授权、无自动 API Key、无赠额、无管理员或财务权限。客户身份创建不等于获得可调用权益。
5. 密码恢复需要邮箱令牌；当前已启用 MFA 时还必须提供当前 TOTP 或未使用恢复码。邮件证明不能关闭、替换或绕过 MFA。
6. 密码恢复成功在同一事务内更换密码、消费令牌、失效同批旧证明并撤销该用户所有会话；锁 family 等待后再次校验证明 TTL。不自动登录，不自动撤销或重发 API Key。撤销使后续会话认证失败，不承诺回滚此前已通过认证的普通业务请求。
7. 请求邮件时，不按邮箱存在、停用、已注册或是否启用 MFA 返回不同状态/正文。不暴露邮箱、令牌、密码、验证码及 SMTP 凭据到审计、遥测或浏览器持久存储。
8. 使用现有实例 guard 与恢复模式；邮件发送不持有身份事务锁，不访问模型/供应商接口，不改变推理资金、采购和安全重试语义。

## 用户场景

- 未登录客户看到注册是否开放；输入邮箱后收到统一提示，通过邮件进入页面，设置密码和租户名称，完成后自行登录。
- 忘记密码的客户请求恢复邮件；打开链接后输入新密码，已开启 MFA 的客户同时提供动态验证码或恢复码；成功后在所有设备重新登录。
- 未配置 SMTP 的开发环境保留现有邀请/管理员创建账号流程；本地 SMTP fixture 可用于隔离联调，不能据此声称真实收件成功。
- 进程在 SMTP 接受后、落库前崩溃，恢复可能重复投递同一封邮件；同一证明仍最多完成一次身份变更。

## 保留与范围外

保留 MFA 默认可选、现有邀请账号及 bootstrap 登录兼容性。新增 `email_verified_at` 不追溯阻止旧账号登录；旧账号不能因字段回填被误标为已经验证。首次恢复可在完整邮箱证明及当前 MFA 成功后记录邮箱验证时间。业务开关目前通过排空/重启生效；关闭是暂停，未批量撤销旧证明，重新开启时尚未过期且未失效的证明仍可用。

本切片不实现修改邮箱、OAuth/Passkey、无邮箱或丢失全部 MFA 的人工恢复、管理员密码接管、邀请邮件、支付、兑换码、订阅、周期预算、媒体/异步任务或 HA。当前已签发 API Key 的处理继续沿用独立的 Key 撤销能力，页面须明确提示密码重置不会撤销 Key。

后续 022 支付以已登录用户和服务端租户身份创建订单；023 周期预算/订阅管理权益，不把邮箱证明变成赠额；024 媒体沿用身份但独立定义任务所有权和计费；025 HA 必须重新验收分布式限流、实例租约和邮件 worker fencing。021 不先行移除单活动实例锁。
