# 021 实施计划

2026-11-01，**已实现 / 限定本地验收通过**。以下实施顺序已执行；结果与范围见[验收记录](../../docs/verification/self-service-identity.md)。真实SMTP与生产门禁保持独立。

1. 集成人审查配置、公开接口、普通开户权限、枚举边界、密码恢复与现有 MFA/会话锁图。明确 022–025 的依赖，先冻结接口与数据合同。
2. 追加迁移：初始化完成标志、用户邮箱验证/密码版本、邮件主体、单次证明与 outbox；既有 admin 库回填初始化，空库 Bootstrap 与标志原子提交。设置约束、受限数据库角色、不可变元数据及受控秘密擦除。不得修改已应用迁移。
3. 实现 config 与能力查询、统一邮箱规范化、摘要/加密域隔离、匿名请求限流及请求邮件事务。公开入口使用严格 DTO、同源检查和实例 guard，不复用要求已登录的 session 中间件。
4. 实现注册完成事务；独立于现有 `CreateTenant` 的默认授权，验证邮箱冲突时不能接管已有账号或租户。验证默认零资金、无模型/Key。
5. 实现密码恢复；先锁当前 user，再锁主体和证明，复用事务内当前 MFA 校验，锁全部 families 后重读时刻校验 TTL；更改密码、密码版本、所有会话撤销及审计原子提交。普通改密也必须递增密码版本；明确在途普通业务请求的既有授权边界。
6. 实现 SMTP transport 与独立有界 worker：只按空闲槽最多 claim 2 条、只锁 outbox，事务外发送，带代际 CAS 的完成/重试；实例失效和恢复模式停止新发送；明确 SMTP 接受后崩溃可能重复投递同一邮件。清理按主体→证明→outbox，覆盖第 5 次 claim 崩溃终结和新密文离线重包。禁止恢复任务发模型请求。
7. 实现登录页入口、请求邮件、注册完成和密码恢复页面；fragment 令牌读入内存后移除，显式确认才 POST。完成/无效/结果不明、关闭与页面 epoch 分离，不保存密码和令牌。
8. 使用本地 SMTP fixture 和随机 PostgreSQL schema/独立角色执行并发、锁等待、崩溃、MFA、会话撤销、枚举和秘密保护验收；执行相关 Go race/vet、前端测试/strict 构建、隔离真实程序浏览器验证。
9. 集成人汇总所有并行改动，更新 HLD/LLD、路线图、统一架构正文、演化记录及内容快照，完成最终只读架构检查。记录真实 SMTP/收件和生产发布外部门禁，不能以 fixture 通过代替。

可并行的实现面：合同冻结后，迁移/identity、邮件 transport/worker、前端可以按固定接口拆分。注册/重置事务和现有 password/MFA/session 的锁序修改由同一实现者统筹；迁移应用、真实程序、架构快照由集成人串行执行。
