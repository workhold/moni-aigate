## A：真实进程故障与部署配置

故障演练须使用最终构建的真实main及隔离本地依赖。每个点由可观察屏障确认已到达，再对该PID执行SIGKILL，记录退出/重启、DB事实、实际外部接收次数和资源清理；单纯改PG行状态不算定点杀进程。屏障只存在于专用QA组件或测试进程，不能增加普通serve任意暂停/注入接口。

| 故障窗口 | 必须证明 |
| --- | --- |
| 身份邮件已claim、尚未SMTP提交 | 重启/lease后可恢复原outbox，不创建第二challenge；generation fencing拒旧ACK |
| SMTP已接受、ACK前 | 可重复同一邮件但不生成新proof；重复消费proof只有一次成功，sent/dead后秘密终态清理 |
| 模型sending提交、上游响应前 | 接班人不重发POST；客户和采购未知各自保留并按原合同收尾 |
| 最终计量证据已提交、结算前 | 重启由原证据唯一结算，不重新执行模型；全部资金/lot/周期事实守恒 |
| 支付外部命令已接受、本地ACK前 | 仅查原命令；回调/query争用同effect，收款/退现不重复（依赖022最终合同） |
| worker lease后旧worker迟回 | 代际CAS只接受当前lease，外部接受与ACK非原子范围明确，不能因此声称exactly once邮件投递 |

021注册/恢复/SMTP配置透传已按[独立A0合同](a0-compose-config-contract.md)补齐九项声明；静态YAML/默认与合成覆盖/迁移环境隔离通过。当前本机Docker CLI没有compose子命令，配置渲染和容器/1Panel/正式SMTP未运行。A其余真实故障与运行配置仍须逐片验收，新增能力默认关闭，应用与projector/owner的环境和权限分离，秘密不进入镜像/公开manifest。022 keyring及后续能力随最终合同接入，不靠生产默认值隐式打开。配置渲染检查不等于Docker运行验证。

## B0：实施前必须公布的共享状态合同

逐项盘点并分类：global/tenant/Key速率与并发、路由/渠道/凭据池许可、探测/发现、密码hash和公开请求上限、邮件/支付/告警worker、周期控制器以及实例恢复排程。区分安全硬上限与可丢失健康提示，后者不得在缓存失效时绕过硬约束。

必须公布真实DDL与Go接口，至少包含稳定instance ID、单调epoch、许可的owner/request/attempt/资源/截止、受控claim/renew/complete状态、所有唯一约束、DB时刻及失效回收证明。共享限流的计数精度/窗口或token算法及降配语义要固定；不能仅写“换成Redis”。所有准入与派发需要同一fencing规则，已发送事实不因租约过期变回not_sent。

“旧owner停顿→新owner接班→旧owner恢复”须逐点裁决。凡旧owner仍可能有已授权网络副作用，必须保守占用至持久执行窗口终止/权威无消费证明；不得让lease失效产生第二次模型POST。worker业务效果仍依不可变source/effect去重，不能只靠分布式锁。

数据库提交窗口、读写分离、事务隔离、父锁/账户/预算/许可顺序、外键隐式锁、故障重试/unknown与最小角色全部在B0冻结。双实例证据通过前保留`InstanceLockKey`，不提供跳过Guard或绕过资金的性能模式。

## C/D：运维与发行出口

固定镜像digest/源码摘要/schema版本、完整默认配置、TLS/反向代理来源与流式timeout、排空升级/回滚支持矩阵、PostgreSQL版本和连接容量。新增SQL只能前进；旧binary不得靠忽略schema校验回滚。

备份至少记录数据库checkpoint/备份摘要及离库财务检查点，恢复到新目标后先只读核验账本、funding/lot、预占、采购unknown、外部effect和会话/证明安全边界。密钥版本从独立秘密系统恢复，不写入数据库备份或报告。报告RPO/RTO须以实测区间与故障前提为准，不从配置估计。

正式SMTP、PSP及供应商adapter的认证各自独立；本地mock只证明实现合同。发行许可选择保留为用户尚未决定的外部门禁，不以“参考设计重新实现”推断所有新增依赖均已审查。生产运维演练完成前不得使用“生产就绪/高可用已完成”的能力状态。
