# 043：路由健康归因修正案（借鉴 magpie A1–A3）

2026-11-26；状态：实施合同。本规格是 [032](../032-phase2-text-data-plane/spec.md) §3.2「健康作用域」的**修正案**：只修正失败到健康动作的映射，不改 032 的重试资格、首事件边界、缓存与预算合同。依据 [magpie 全量研究](../../docs/research/magpie/gateway-routing.md) §3 条目 1–3（`forbiddenAlike` 归因、分类型 rest、overloaded 单列）。前置：main `fb2146f6`（032/033/041-P0/报表修复已合入）。

## 1. 现状缺口（审计结论）

1. 裸 5xx 一律计入渠道熔断爬梯：被上游固定拒绝的请求（内容触发、请求形状问题）连续失败会误熔断整个渠道+模型池（`internal/server/gateway.go` 的 `outcome()` 与 `internal/routing/routing.go` 的 `Finish`）。
2. 429 冷却作用域是 `channel:model`：池内一个凭据被限流会让同渠道同模型的全部凭据一起冷却（`HealthKey = channelID + ":" + upstreamModel`）。
3. 上游过载（HTTP 529）没有独立失败类：现计入 `upstream` 类并参与熔断爬梯，供应商繁忙会让所有账号逐个爬梯休息。

## 2. 与 032 原合同的关系

| 032 原文 | 本修正案 |
|---|---|
| 失败类→作用域→动作表（spec §3.2） | 修正：`rate_limit` 作用域从 channel+model 改为凭据成员级；新增 `overloaded` 行；`upstream` 类增加归因前置 |
| 熔断参数是路由策略版本字段（`failure_threshold/open_ms/half_open_tokens`） | 不变。归因窗口、成功近因窗口与过载短休时长是固定常量，不进入路由版本 |
| 健康状态进程内、重启清空 | 不变。归因账本、成功近因与凭据冷却同为进程内可变状态，重启即清空；持久隔离仍只用于凭据、binding 与额度 |
| 重试资格只由 `Consumption` 决定 | 不变。归因只撤回健康动作，永不改变 `SafeToRetry`/`Consumption`/attempt 预算/首事件边界/唯一结算 |
| 新增失败子类不得改变对外错误码白名单 | 529 改分类后客户仍见原 `upstream_rejected`/502（429 仍 429）；`no_consumption_event_codes` 白名单不变 |

本修正案不修改 033（动态路由/粘性）、041（毛利与执行合同）、035 的语义。041 的 `margin_basis_unavailable`、`cumulative_cost_unavailable` 等准入排除继续不算渠道故障，与本修正案无关（准入过滤在候选过滤层，不在健康动作层）。

## 3. A1 归因先于休息

一个被上游以确定性错误拒绝的请求，不应把整个渠道+模型池计入熔断。magpie 用「同请求、同供应商同模型、两个账号、同样的拒绝，且供应商刚回答过别人」判定为请求的错并撤回休息（`internal/gateway/routing.go:114-221@e66d872`）。

**aigate 适配（与 magpie 的结构差异必须显式声明）**：magpie 在同一请求内把失败轮换到同供应商的另一个账号；aigate 的冻结合同禁止这样做——032 spec §3.1「最多两次 attempt（跨渠道），不在同渠道换 Key」，且 `model_bindings` 对 `(route_policy_version_id, channel_id, upstream_model, variant_key)` 唯一，安全重试的 `tried` 集合按 binding 排除已试渠道。因此 aigate 的归因证据按**时间窗内的跨请求配对**收集，不以「同一请求」为必要条件：

**归因条件（全部满足）**：渠道+上游模型上一次失败被记录为可归因失败时——

1. 失败类为 `upstream`（裸 5xx，携带上游 HTTP 状态码）；
2. 该渠道+上游模型的归因账本中存在一条账目：**相同失败类 + 相同上游状态码**（精确相等，不做段/区间合并）、**不同凭据**（两个账号）、且账龄 ≤ 归因窗口（60 秒）；
3. 该渠道+上游模型在**近 5 分钟内有过可信成功**（`Success` 结局）。

**归因动作**：判定为请求的错——本次失败不计入熔断爬梯、不施加任何 rest；同时**撤回**所配对账目当初增加的计数（`failures` 减一，下限 0）。打开状态本身不可被归因触碰：每次打开/隔离/短休都递增 generation，延迟到达的旧完成整体丢弃，仍能落账的完成只属于未打开的当代。半开状态下被归因的探针失败只归还令牌并保持半开，不重新打开。配对消耗双方账目（一条账目至多被撤回一次），未配对的单次失败照常计数。

**不比较错误原文**：只比较机器信号（`FailureClass` + 上游状态码），不匹配人类消息；这与 `classifyUpstream` 现有口径一致。

**窗口常量**：归因窗口 60 秒；成功近因窗口 5 分钟。二者是本规格的固定有界常量，不是路由版本参数（理由：熔断参数版本化是 032 的既有合同，本修正案不扩版本合同；固定常量在 LLD 与统一架构中登记）。

**明确排除**：429/配额/凭据类、无上游状态码的失败（网络、超时、协议中断）不参与归因——它们要么已不计渠道故障，要么没有可配对的机器信号。供应商真实故障（近 5 分钟无成功）永远不触发归因，熔断照常。

## 4. A2 限流冷却下沉到凭据

**作用域**：`rate_limit`（429 及规范化为限流的机器码）的冷却从 `channel:model` 下沉为 `channel:model:credential`（凭据池成员级）。一个凭据被限流只冷却该凭据在该渠道该模型上的使用；池内其他凭据继续参与抽签。渠道级熔断只由非凭据特定失败驱动（`upstream` 归因后余量、`network`、`timeout`、`protocol`）。

**时长**：保持 032 现状不变——上游 `Retry-After` 优先，缺省 30 秒，上限 5 分钟。不新增路由版本字段；`failure_threshold/open_ms/half_open_tokens` 仍只作用于渠道级熔断。

**配额类不变**：`quota` 现状已是持久凭据隔离（撤销 + 审计），本修正案不动它。

**候选过滤与可见性**：凭据冷却是运行时可变准入状态，作为成员级排除实现，排除理由 `credential_cooldown` 进入路由决策记录（只读回放按既有规则呈现）。池内尚有可用成员时，binding 整体仍可选（凭据级排除不污染 binding）；全部成员冷却时 binding 以 `credential_cooldown` 被排除，全部候选无可用时按现行 503 `no_available_channel` 快速返回。033 粘性的 `break_on: health` 把 `credential_cooldown` 与 `circuit_open` 同等对待（否则粘性会话会在 429 场景相对现状发生语义回归）。

## 5. A3 overloaded 单列

**分类**：上游 HTTP 状态码 529 归类为新失败子类 `overloaded`（机器信号，符合「只认机器码与 FailureClass」口径）。`classifyUpstream` 对 ≥500 一律不做错误正文机器码匹配的现状保持不变——更广的 overloaded 识别（如 503+机器码）在拿到供应商证据前不做。

**健康动作**：固定短休 30 秒，作用于 `channel:model`（供应商忙不是账号的错）；**不计入熔断爬梯**（`failures` 不增）；**不持久化**（随进程内存，重启清空）。短休是固定常量，不受路由版本 `open_ms` 影响。

**不改变的边界**：`Consumption` 仍为 `unknown`（529 不进任何无消费白名单，不授予重试）；客户可见错误码不变（仍为现行 `upstream_rejected`/502 映射）；计费与首事件边界不变。

## 6. 验收

故障注入矩阵在专用 PostgreSQL（随机 schema）上断言：

1. **A1 归因**：同渠道同上游模型两个凭据在归因窗口内以同失败类+同状态码被拒、且渠道近 5 分钟有成功 → 计数被撤回，熔断不打开，后续请求正常路由；无近期成功时同场景照常熔断（反例）；不同状态码或同凭据重复失败不配对（反例）。
2. **A2 作用域**：一个凭据 429 冷却后，同池其他凭据仍被选中；`Retry-After` 边界（缺省 30 秒、上限 5 分钟）不变；路由决策出现 `credential_cooldown`；全部成员冷却时 503 `no_available_channel`。
3. **A3 短休**：连续 529 不增加爬梯计数（阈值配置的熔断不因此打开），固定 30 秒短休生效，重启语义不变（内存态）；客户响应与计费字段与现状逐字段一致。
4. **回归**：既有熔断参数按路由版本隔离；首事件边界；`unknown` 消费恰好一次上游接收、不重放；041 准入排除不算渠道故障；相关包 `-race` 通过；`make check` 通过。
5. 最终干净提交在专用环境运行完整 serial-v1 [029](../029-phase1-acceptance/spec.md)；局部与专项不替代该项。
