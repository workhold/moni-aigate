# Billing contract v0.1 (r3)

Written before implementation. All exported operations use structured input and a context. This module owns migration 002 and never calls an upstream provider.

* `New(*pgxpool.Pool) *Store` uses READ COMMITTED and one explicit `pgx.Tx` per financial operation. Every helper receives that transaction. Money is integer CNY micro-units, encoded as a decimal JSON string.
* `CreateCredit(CreditInput)` records a globally unique external business reference. Credit/refund creation requires `IdempotencyKey` and `RequestHMAC`, permanently scoped by `(tenant,operation,key)` in `financial_idempotency`; equal digest returns the original order and changed digest conflicts. An active `finance_operator` creates the order; a different active `finance_approver` approves via `ApproveCredit(ApprovalInput)`. Approval, journal, balances, audit and outbox commit together. Repeated approvals return the original order.
* `Reserve(ReserveInput)` rechecks tenant/member/user/Key/model permissions under the parent-row lock protocol. It validates the supplied upper input and output limits against the model profile, selects the DB-time effective price, and computes R with arbitrary precision. The caller cannot supply a charge. AVAILABLE→HELD, Key held, request, permanent reservation journal, recovery job and outbox commit together. Reused inference idempotency keys never dispatch again: same digest returns `request_exists` plus original request ID; different digest returns `idempotency_conflict`. The Store registers live requests before commit; the caller must `defer EndRequest(requestID)` after successful reserve.
* `RecordAttempt(AttemptInput)` records prepared state and immutable provider cost rates. `PrepareDispatch(DispatchInput)` locks current auth parent rows with SHARE and reads grants in subsequent READ COMMITTED statements, verifies current channel/credential/region restrictions, commits sending, then returns. Only then may the gateway send. An ambiguous commit must not cause dispatch.
* `RecordFinalization(FinalizationInput)` is T1.9. It appends only normalized usage and protocol/transport/local delivery facts, with profile and fixed billing policy. Confirmed final usage requires nonnegative input/output/total and `input + output = total`, with cache/reasoning as subsets. Missing, provisional, estimated and conflicting usage are never final invoice evidence. Content delivery facts are monotonic across appended finalizations. Source identity is `(tenant,source,source_event_id)`; repeated equal usage is not accumulated. Equal identity with different payload preserves the original, records the conflict and enters reconciliation. A finalization ID provides separate append-operation idempotency. No text, headers, URLs or provider error bodies are accepted.
* `Settle(SettleInput)` is T2: lock the request reservation, inspect immutable facts and mode, DB clock, then charge at most R or release or mark pending. Normal live completed calls can charge before request deadline. Recovery of a disappeared non-stream/no-output request releases; partial output or explicit client cancellation with trustworthy final usage can charge. Unknown delivery/usage waits. Existing settlement always returns unchanged, including after a lost commit response. The 24h financial deadline wins even if trusted evidence arrived earlier; all affected account locks are acquired before the last DB-clock check, so lock waits cannot extend charge eligibility. No late customer charge after release. Client spent does not decrease on refunds.
* `Release(ReleaseInput)` only accepts a finite internal non-charge reason and records a zero-charge settlement; it cannot undo an existing charge. `MarkPending(PendingInput)` preserves the hold and original deadline. `Recover(RecoverInput)` durably claims recovery jobs, skips live requests, scans unfinished reservations even if notifications were lost, and only invokes T2. It never generates or resends.
* `CreateRefund(RefundInput)` / `ApproveRefund(ApprovalInput)` append a journal linked to the original settlement; maker/checker and total refund <= actual charge are transactionally enforced. Refunds return wallet funds, not cash, and do not restore Key lifetime budget.
* `Reconcile(ReconcileInput)` supports `propose` (operator, controlled evidence reference plus reason), `approve` (different approver), and customer-favorable `release` (approver, reason, pending hold only) for trusted normalized usage. Proposals are not automatically billable. Approval and settlement share a transaction and the original deadline. Expired holds release without charging.
* `RecordCostCorrection(CostCorrectionInput)` adds an independently idempotent provider cost fact, never edits price snapshots or customer funds. Unknown provider cost is NULL/unknown, not zero.
* `Wallet`, `Journals`, `Requests` and `Report` are tenant-scoped. Wallet reads synchronous ledger balances. Report consumers use stable outbox IDs and transactionally commit a receipt and aggregate update; projection replay cannot create a journal. `Project` replays internal events; `VerifyLedger` compares balances with immutable entries.

Persistent IDs are UUID strings. Tables owned by this module: request_records, request_idempotency, reservations, upstream_attempts, metering_events, metering_event_conflicts, finalization_records, settlements, ledger_accounts, journals, journal_lines, credit_orders, refund_orders, reconciliation_cases, recovery_jobs, billing_profile_blocks, provider_cost_corrections, projection_outbox, projection_receipts, report_totals, active_report_projection, financial_idempotency. Core tenant/user/Key/model/price/cost/audit tables are owned by migration 001.

Financial headers/lines and evidence are append-only. Deferred database constraints reject unbalanced or empty journals, and prohibit adding entries to a journal from another transaction. Cache balances and entries are written together. Untrusted HTTP code must derive Principal from authenticated context; this is an internal service contract, not a public external metering endpoint.

Errors expose a stable `Code` and optional original resource ID. Integration tests use a real PostgreSQL instance from TEST_DATABASE_URL, isolated in a temporary schema; absence explicitly skips integration tests and must never be reported as a pass. Exact runnable evidence will be recorded after implementation.

Projection contracts:

* `Project(ctx, ProjectInput) (int, error)` consumes at most 200 retained outbox facts per transaction. An empty consumer reads `active_report_projection`; the initial consumer is `reports-v1`. Stable receipt insertion and NUMERIC aggregate update share a transaction. Cost-only events do not inflate financial aggregates. Lifetime report totals are decimal strings, independently of BIGINT wallet limits.
* `VerifyLedger(ctx, Query) (LedgerCheck, error)` compares all immutable entries with cached account balances and journal balance. Empty tenant scope is an internal global verification; tenant queries cover that tenant's customer accounts and journals.
* `Rebuild(ctx, consumer string) (int, error)` requires maintenance mode with all business writers/workers stopped and the instance lock held by the CLI. It rebuilds an inactive consumer from retained facts, verifies receipt coverage, every tenant's credit/charge/refund/release/request totals against synchronous source records, and ledger balance; only then atomically switches the active consumer with an audit record. A failed or crashed rebuild leaves the previous active consumer intact and can resume the candidate. Routine projectors follow the active consumer after restart.
* Routine projector SQL permissions: schema USAGE; SELECT `active_report_projection`, `projection_outbox`; SELECT/INSERT `projection_receipts`; SELECT/INSERT/UPDATE `report_totals`. It has no authority over financial facts, balances, Key usage, journals, audit, or outbox mutation. The maintenance CLI uses the application pool for source verification and active-pointer/audit writes, while no HTTP server or worker runs.

Validation commands: `go test ./internal/billing` and `TEST_DATABASE_URL=... go test -race -count=1 ./internal/billing`. Integration fixtures create isolated schemas and execute actual migrations on PostgreSQL. Test results are recorded only after execution; a missing database is an explicit skip.

Tests cover permanent inference/financial idempotency; shared-wallet/shared-Key races; T0/T1/T2/T3 rollback at balance/Key/audit/outbox boundaries; trusted zero vs missing/conflicting usage; live/recovery/cancellation/partial-output policy; hard24h even across account-lock waits; retail snapshots, R cap and profile pause; maker/checker roles, refund cap and unchanged Key spent; immutable balanced journals and cross-tenant rejection; durable recovery and concurrent worker claims without creating upstream attempts; monotonic delivery facts, latest-only retry proof and older append replay; projection rollback, duplicate/concurrent receipts, restricted database role, rebuild verification and atomic active-consumer switching.

The in-process role model and financial tests do not replace payment-provider reconciliation, whole-process kill tests, backup/RPO/RTO drills, or production load tests. Those remain separate acceptance work owned by the integrated application; the billing package does not declare commercial readiness.

Implementation refinement after capacity measurement: `lockAccounts` now takes only the operation's required kinds, initializes them in one SQL statement, then locks selected account IDs in sorted order. Reserve does not lock global platform funding/revenue accounts. T2 reuses its already locked account snapshot and performs the hard deadline check after that acquisition. Normal model synchronization is SHARE; only actual profile tightening (`raw > R`) takes UPDATE before money writes. Explicit PostgreSQL transaction-aborted errors 40P01/40001 may retry at most twice; unknown commit/network outcomes never trigger automatic retry. New regression tests hold unrelated funding/model locks, verify normal inference completes, and inject known SQLSTATE aborts to prove rollback and bounded retry.

`ReserveInput.RouteRevision` is persisted as `request_records.route_revision`; a positive revision must match the locked model's current revision at T1. RecordAttempt verifies channel/version/upstream against that retained published binding. Zero is retained for internal legacy fixtures only; the actual gateway supplies the model revision. Existing reserved requests continue using their original immutable snapshot after a later publication. The route-snapshot and scoped-lock tests passed in real PostgreSQL with the race detector.

Evidence/proof references are opaque controlled record IDs (letters, digits, `:_./-`, at most256bytes), not URLs, query strings, JSON, API credentials or evidence content. Resolve the ID in a separate authorized evidence system. Free-text reason fields must not contain secrets or inference bodies.
