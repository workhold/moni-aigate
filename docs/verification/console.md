# 控制台与身份验收记录

验收日期：2026-10-30。范围为 `001-commercial-mvp` 控制台与身份合同。以下结果来自本机 Go/Gin 后端、PostgreSQL 16.15 与 Chrome，未接入真实供应商、支付系统或生产客户。

## 运行环境与证据

- 浏览器：Chrome 扩展控制，真实页面 `http://localhost:58123`，生产构建由 Go 嵌入提供。
- 数据库：真实 PostgreSQL；集成测试各自创建随机独立 schema 并应用正式 migrations，结束后删除该 schema。
- 浏览器数据：专用本地测试库中的虚构客户、平台角色、模型与核款凭证，不代表实际收款。
- 绑定密钥、恢复码、完整 API Key、密码未写入本记录、截图或版本控制。API Key 创建后随即撤销。
- [真实客户钱包截图](assets/console-wallet.jpg)：仅显示测试客户余额与核款流水。

## 自动验证

执行：

```sh
cd web
npm test
npm run build

# 仓库根目录，TEST_DATABASE_URL 指向专用本地测试数据库
go test ./internal/identity ./internal/server -count=1
```

结果：前端 4 项测试通过，严格 TypeScript 检查与 Vite 生产构建通过。设置真实 `TEST_DATABASE_URL` 后，identity 与 server 测试均通过，无数据库跳过（最近一次分别为 4.664 秒、4.511 秒）。测试覆盖：

- Cookie 属性、Origin、CSRF、过期会话、客户端租户注入与跨租户资源访问。
- MFA 初次设置的近期密码要求、恢复码账号绑定、恢复码一次使用与 TOTP 防重放。
- MFA 启用后其他旧会话撤销、租户切换轮换、退出后的旧会话无法恢复。
- Key 创建时重读成员当前角色、部分 PATCH 保留授权后的委派边界、owner 无法授予自身没有的模型。
- 平台管理、财务制单与审批角色隔离，客户敏感写入的近期再认证要求。
- 财务客户选择列表只提供客户 ID、名称、状态，不暴露所有者邮箱或模型/地域授权。

`internal/server/gateway_integration_test.go` 由网关验收负责，和本文件的身份测试共用真实 PostgreSQL 环境，但使用独立 fixture。

## 本轮发现并修复

- 首次平台登录同时返回 `mfa_required` 和 `enrollment_required` 时，前端原先会误停在验证码登录页；现优先完成绑定。
- 登出与 `/me` 失败时清理 MFA 绑定状态，避免上一账号的状态影响下一次登录。
- 成员停用状态与正式 schema 统一使用 `suspended`。
- 真实集成测试发现的会话退出恢复、MFA 旧会话、Key 角色降级、owner 部分更新委派、设置 MFA 再认证与财务列表投影问题，已在后端修复并由测试回归。

## 验收边界

本轮浏览器未发送真实供应商请求，未执行收费渠道探测，未验收生产部署容量。上游调用、SSE 与计费并发的验证以网关和账本集成测试记录为准。钱包累计入账/累计消费若 API 未返回聚合字段，界面显示“—”，不会将未知值显示为零。

测试账号的 MFA 只用于本轮验收，不作为交付账号或生产默认凭据。交付者需使用独立 review 账号自行绑定验证器。

## MFA 绑定引导增补

安全页补充 Google Authenticator / Microsoft Authenticator 等 TOTP 应用的添加步骤，明确应用每 30 秒显示新的 6 位数字，网页不生成登录动态码，也不发送短信。恢复码单独说明，避免将其作为绑定动态码。新增浏览器本地生成的二维码与手动密钥/URI 备用入口；新增待绑定阶段“重新生成绑定信息”确认，提醒旧密钥、二维码和恢复码失效。后端强制 MFA、近期密码再认证和已启用账号的重置规则未修改。

本次验证：前端 5 项既有测试通过，严格 TypeScript 检查和 Vite 生产构建通过；使用完全虚构的 otpauth URI 生成 240px 二维码，由 Apple Vision 独立解码并确认内容逐字相同，临时图片随验证结束清除。运行依赖固定为 `qrcode@1.5.4`（MIT），类型包为 `@types/qrcode@1.5.6`（MIT）。代码审查确认二维码只写入页面内存，不使用远程二维码服务，不进入 localStorage、URL 或日志，离开页面或成功启用后清除临时绑定内容。

以上是代码、构建及合成二维码验证，尚未代替真实手机扫码与完整绑定验收。本次没有读取或计算用户的真实动态码，没有启用、重新生成或修改用户 review 账号的 MFA；嵌入 Go 的前端更新需重新编译后端并重启预览后可见。

集成时在`enable()`中同步检查恢复码保存确认，覆盖直接触发表单提交的路径。最终5项前端测试、严格TS/Vite构建、Go嵌入构建通过；已重启本工作区58123预览，`/health/ready`为200，HTTP实际返回的入口与SecurityView哈希资源逐字匹配最终`web/dist`。用户刷新安全页后可见新引导，自行开始或重新生成绑定；未代其执行绑定操作。

同日开发者随后要求MFA默认可选，原强制要求已由[ADR-003](../decisions/ADR-003-optional-mfa.md)覆盖。当前默认未绑定即可进入业务，扫码仍保留；真实浏览器与回归证据见[MFA可选策略验证](mfa-policy.md)。以上早先强制模式的QA只描述当时行为。
