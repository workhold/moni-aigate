# 竞品研究汇总与 moni-aigate 的融合取舍

状态：DRAFT / 设计输入；2026-10-30（Asia/Shanghai）。原始清单已放入 [README](../../README.md#竞品与相关项目)。

## 1. 研究方式与深度

这轮对 New API 做关键请求、流式解析、预扣结算和支付回调的源码追踪；1Panel-Gateway 没有公开网关实现，研究限于固定仓库和官方产品文档。新增项目采用固定版本的 README、许可证和代表性源文件做定向比较，没有完整审计或运行每个系统。源码机制、产品声明、企业功能和待实现建议分别说明。

开发者已确定独立实现 moni-aigate。以下项目都是设计参考，不成为当然的代码底座、依赖或组件拼装清单。

扩展轮通过 GitHub 搜索/Repository API 固定身份与SHA，并实际用 Chrome 阅读 GitHub 与官方文档；新增9个项目组及OpenRouter产品参考。项目组可能包含多个仓库（如Helicone、Lago），不按URL重复计作多个竞品。维护状态仅反映2026-10-30访问时点。

## 2. 分类比较

| 项目 | 核心参考价值 | moni-aigate 采用方式 | 研究边界 |
|---|---|---|---|
| 1Panel-Gateway | 账号池、模型/用户组、权限治理、自助Key、运维体验 | 商业运营后台的产品基础；独立Compose/1Panel交付 | 给定仓库无网关源码，内部实现不可验证 |
| One API | 用户/令牌/渠道、分组模型可用性、权重选择的基础模型 | 保持基础实体简单；明确API客户与上游渠道分离 | 不将历史基础模型当作完整资金账本保证 |
| New API | 适配器、商业运营、价格、预扣/实际结算、支付与日志 | 参考商业流程和协议边界，自行实现资金核心 | 两个组织URL指向同一仓库；固定提交研究不冒充全量审计 |
| Moni-AI | 原始清单称其为动态调度网关 | 暂不据此设计特定算法；保留为待验证候选 | 给定Gitee地址访问404，无法核查源码、许可和动态调度；不能证明没有公开GitHub |
| ChatAPI | 自托管令牌/渠道治理和快速兼容入口 | 对照简单运营流程，避免首版功能膨胀 | 许可证与实现范围见国内研究，不等同于New API现版本 |
| LiteLLM | 策略边界、预算reserve/reconcile/cancel、fallback去重和再验权 | 统一尝试预算、总时限、取消及预算边界 | SDK/Proxy路径与企业目录分开；预算不等于财务收款账本 |
| Bifrost | Go请求管线、失败分类、逐次attempt成本与观测 | admission/route/attempt/usage/settle分层，成本按尝试保存 | 不继承宣传性能；特定熔断企业说明不当作开源实现 |
| Portkey | 有schema约束的路由、weight/fallback/retry/deadline | 首版用扁平、版本化配置，拒绝循环和无边界回退 | 托管vault/缓存等不直接算开源自托管能力 |
| Higress | AI策略生命周期、token治理与流式观测 | 参考阶段划分与指标，保留简单可测试接口 | 不引入Envoy/Istio/Wasm整栈，不把限流当钱包预占 |
| APISIX | 通用网关插件边界、AI准入和响应usage计数 | 明确请求准入、响应计量与账本提交职责 | 不引入etcd/多组件控制面；token计数不是资金事务 |
| Open WebUI | 面向人的聊天前端、OpenAI兼容连接方式 | 后续作为可选外部客户端，本项目仍有自有运营/客户控制台 | 不是售卖API的网关；当前许可有品牌条件，不能笼统称MIT |
| TensorZero | 不可变配置快照、候选完整性、实验边界 | 配置校验与原子发布，历史请求绑定版本 | 已归档，仅历史设计参考；不引入其数据栈 |
| Plano（原ArchGW） | 语义候选、会话绑定、切换与缓存成本 | 首版固定逻辑模型，后续auto商品评估完整会话成本 | 托管路由模型与开源代理分开；不默认外发客户内容 |
| RouteLLM | 强弱模型路由、阈值校准、质量评估 | 后续以业务数据分层评估，显式模型商品与价格 | 可见推送停在2024-08；所读实现仅最后消息，不能泛化多轮工具质量 |
| Lago | 事件归属、交易来源、提交后通知 | 资金事实先提交，通知/报表副作用另行幂等 | AGPL；读取固定API子模块部分链路，不声称全钱包审计 |
| OpenMeter | 事件摄取/去重、ledger更正和投影职责 | source/event命名空间、原始分录追溯、投影重放不扣款 | 当前已有ledger/credits/billing；202接受/TTL去重不等于永久结算唯一 |
| Unkey | Key验证管线、权限/速率/credits结果分类 | 结构化Key判定，运行时限流与PG资金分开 | 当前根FSL有竞争使用限制，不笼统按MIT复用 |
| Helicone | 独立网关的真实策略、观测平台的URL脱敏 | 首版脱敏；同模型自适应策略后续影子评估 | 两仓库分开；旧网关GPLv3与README Apache冲突，当前服务文档不等同旧源码 |
| Langfuse | 稳定采样、批处理上限、评估 | 观测与资金事实分离，有界资源；评估后置 | 核心/企业目录分区许可，首版不强制外部部署 |
| Agent Router（原Envoy AI Gateway） | 隐私开关、协议指标、usage窗口语义 | 元数据白名单与阶段指标，保持一个收费/重试控制点 | 已迁移，含standalone路径；用量限流不能替代余额预占 |
| OpenRouter（商业产品文档） | 模型/供应商分层，硬限制与软偏好 | 请求只能收紧策略；过滤后排序，不静默丢参数 | 不声称服务端开源；地区/ZDR是需核实的产品合同，非moni现成功能 |

这些能力属于不同层。将它们全部部署起来会增加重复鉴权、重试放大、账单归属和故障排查复杂度；moni-aigate 选择在自己的边界内实现所需行为。

## 3. 对设计的实际调整

1. **治理与商业分域**：1Panel式账号池/授权体验和New API式商业流程组合，客户模型与平台渠道解耦。
2. **调用管线明确阶段**：准入、路由、上游尝试、流式计量、资金结算分开；每阶段记录版本和结果。
3. **一个请求、多次尝试、一次收费**：客户按固定售价唯一结算；供应商成本按每个attempt保存合同快照和计量来源。
4. **失败必须分类**：参数错、凭据错、限流、上游故障、已发送后结果未知分开；只有可信无消费才透明重试。
5. **路由有边界**：最高可用优先级池内按权重选择，过滤权限/能力/健康/容量；最多两次attempt、候选去重和总deadline。
6. **资金核心持久化**：PostgreSQL原子冻结、平衡流水、退款补偿、未知消费核对；Redis/Token限流不能替代它。
7. **数据面保持轻量**：首版Go单体+PostgreSQL；自适应评分、响应缓存、递归DSL、多实例共享状态单列后续规格。
8. **配置发布完整且原子**：不可变策略/绑定版本，拒绝空池、重复与悬空引用；失败保留旧版，请求保存版本；紧急停用不能被旧快照绕过。
9. **硬约束不能被偏好扩权**：权限/能力/地域先过滤，优先级/权重再排序；外部header、模型后缀和请求参数不能授予渠道或租户身份。
10. **计量与统计的重放边界**：事件/attempt/资金操作各有身份；资金事务保存待投影事实，报表重建与未来通知重发不能再次收费。
11. **观测完整性分级**：资金/结算证据/成功敏感变更审计完整持久；拒绝类安全信号与非权威遥测有界记录并暴露丢弃计数，统一脱敏且默认不留正文。

这些补强已映射到LLD和SDD的FR-12、NFR-07及AC-34~40；均为待实现合同，未执行任何业务验收。

进一步的r3校准沿实际HTTP调用者、事务、降级和测试源码追踪，纠正了最终分组价格、局部fail-closed、隐式重试和隐私开关的外推；增加交付/收费矩阵、可信最终usage、终结证据和恢复裁决。具体变化见[源码校准汇总](design-calibration.md)，验收细化到AC-52，全部待执行。

## 4. 第一版与后续

| v0.1必须落地 | 后续另立规格 |
|---|---|
| models + 文本Chat非流/SSE、基础工具调用 | Responses/原生Claude/Gemini、多模态/异步任务 |
| 客户租户、模型授权、一次性Key、钱包和Key上限 | 自助开放注册、分销与复杂套餐 |
| 人工核款审批、原子预占结算、退款及异常恢复 | 在线支付、支付原路退款/拒付和税务票据 |
| 同模型优先级/权重/健康/并发路由、有限安全重试 | 成本/延迟/质量自适应调度、语义路由 |
| 元数据日志、request/attempt关联、独立部署恢复 | 内容留存、租户隔离缓存、OTel外部集成、多实例 |
| 配置原子发布、硬约束过滤、Key判定、内部统计投影幂等 | 语义auto商品、会话切换优化、业务数据集评估与影子策略 |
