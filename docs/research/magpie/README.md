## 一句话结论

**magpie 的定位是"把订阅配额用干净、让编码 agent 不中断"的单运营者本机/局域网网关；aigate 的定位是"质量/成本/毛利约束下选供应商，且每一分钱可核对"的多租户商业网关。两者同为"多上游、多协议、失败切换"，但目标函数相反。** 因此对照的结果不是"aigate 落后了多少"，而是三件事：哪些设计模式可以直接借鉴、哪些是 aigate 有意不做的、哪些是 aigate 自己的现存缺口。

## aigate 反过来领先的部分

为避免把对照读成单向落后：租户隔离与三角色数据库分离、钱包硬预占、唯一结算与 funding lot、候选级与请求级累计成本的毛利准入门（`internal/economics/admission.go:39-101`）、不可变发布版本与 CAS 激活/回退、发布证据门禁、质量证据与质量政策、完整候选失败池落库与确定性回放、租户/Key/采购三级周期预算。这些在 magpie 中**没有对应物**，也是下面所有借鉴点必须绕开的约束。

## 最值得借鉴的设计（跨三册合并，按建议顺序）

### A. 路由与故障处理 → 032 / 033

| # | 设计 | 解决什么问题 | 成本 |
| --- | --- | --- | --- |
| A1 | **归因先于休息**：同一请求被同供应商两个账号同样拒绝、且该供应商刚答过别人 → 判定是请求的错，不熔断整池 | 一个被上游固定拒绝的请求不该拖垮整个账号池。aigate 裸 5xx 仍计渠道故障 | 中 |
| A2 | **限流冷却下沉到凭据**：只歇被限流的那个 key | aigate 现在 429 冷却按 `channel:model`，池内一个 key 被限流会冷却整个渠道 | 低 |
| A3 | **overloaded 单列**：供应商忙是固定短休、不计失败、不爬梯 | 避免"八个账号各歇十分钟" | 低 |
| A4 | **粘性量化判据**："缓存读+写 ≥ 1024 且未冷才值得保持" | 给粘性一个可计算的理由（数值必须用 aigate 自己的供应商实测） | 中 |
| A5 | **回合内决策保持**：工具循环期间不搬家 | 粘性现只有 `max_age_s`，没有"回合"语义 | 中 |
| A6 | **全池冷却时合成 Retry-After** | aigate 现在统一回 503 `no_available_channel`，客户端不知道等多久 | 低 |
| A7 | **并发突发分散**：同权候选用在途数做平局裁决 | 同时到达的请求会全压到同一个账号 | 低 |

### B. 界面与信息设计 → 控制台

**magpie 最值得学的不是外观，而是三件事：每个决策都配一句人话、每个额度窗口都有进度 + 重置 + 节奏、解释默认藏起来。**

| # | 设计 | aigate 落点 | 后端数据 | 成本 |
| --- | --- | --- | --- | --- |
| B1 | **路由决策叙事化**：一句话结论 + "请求了什么 → 为什么排第一 → 每次尝试结果 → 上游原话" | `RouteAttempts.vue` | 已有 | 纯前端 |
| B2 | **额度窗口三件套**：进度条 + 重置倒计时 + Pace（比匀速快/慢多少） | 周期预算面板、密钥列表 | 已有 | 纯前端 |
| B3 | **上下文占用条**：已用/窗口 + 健康词 + 余量估计 | 请求明细 | 占用比已有，分项没有 | 纯前端 |
| B4 | **说明文字按需显示**：规则一行常驻，长解释悬停才出现 | 全站 `el-alert` / `section-note` 治理 | 无 | 纯前端 |
| B5 | **密钥列表收窄**：行内药丸 + 行下用量行，次要动作收进"更多" | `KeysView.vue`（390px 下 330px 固定操作列是主要溢出源） | 已有 | 纯前端 |
| B6 | **模式 chip 即入口 + 一句话解释** | `RouteEditor.vue` | 无 | 纯前端 |
| B7 | 经营报表：紧凑 KPI 条 + 份额条 | `OperatingReport.vue` | 已有 | 纯前端 |
| B8 | ⌘K 页面/设置搜索 | `App.vue` 顶栏 | 无 | 纯前端 |

其中 **B1 是与你产品目标最直接相关的一项**：magpie 的路由组规则编辑器用自然语言把"为什么这次请求走了这个模型"直接摆在用户面前——

> 当 `≥ 128000 tokens` / `带图片` / `意图是「用户想做什么」` → **先发给** `kimi-k2.5`

规则一行一条、自上而下检查、命中即排序。这正是 041 "显式动态商品"（用户以为用 K3、编码阶段实际走 DeepSeek）的产品化表达，比抽象的 `TaskPolicyVersion` 可理解得多。**建议在 041 P1 的 K3-Dynamic 商品页上直接采用这种"规则行"表达来公开候选范围与切换条件**——它同时满足 041 对动态商品的披露要求（公开候选、适用场景、质量下限）。

## aigate 应保持不做的

这些**不是漏做**，而是与 aigate 的资金不变量或产品定位冲突。逐条理由与规格出处见 [gateway-routing.md §4](gateway-routing.md)。

- **宽松切换与原位重试**（401/403/429/5xx 即换手、同候选重试、patience 等待）：可能已消费的请求重发等于替客户多付一次钱。aigate 只认无消费证据（`specs/032-phase2-text-data-plane/spec.md:31-36`）。
- **提交前给客户端发心跳**：一旦写出字节就算提交，之后不能再换手。aigate 选择"首事件通过前什么都不写"以保留切换权（`docs/design/LLD.md:445`）。
- **在线 LLM 意图分类器读客户正文**：隐私与成本；041 非目标（`specs/041-profit-hybrid-platform/spec.md:31`）。aigate 的任务分类只用 SKU 默认类 + 受控 hint + 有界本地分类器。
- **订阅账号代理 / 驱动本机官方客户端**：服务端无法也不应驱动用户本机二进制；转售订阅有条款风险。aigate 把它划给 Sub2API 叶子且条件启用。
- **JS/Bun 插件运行时与社区中间件市场**：路由、计量、结算、恢复、审计不可插件化（`specs/032-phase2-text-data-plane/spec.md:120-138`）。
- **网关内 web search / `web_fetch` / MCP 托管**：工具调用的计量计费、多轮预占、租户隔离、出口安全都没有合同。（但见 C3——"计量化 Web Search"是值得评估的产品方向，前提是先把合同冻结。）
- **执行器多跳级联**（远程 magpie 套远程 magpie）：无逐跳成本归因与证据合同；041 的 `max_relay_depth` 封顶为 1。
- **运行时"学习式"请求改写**（记住某供应商拒过哪个字段、下次自动去掉再发）：对已发请求的任何再发都是第二次生成。aigate 把这类差异冻结进 profile 与资格证据。
- **"把配额用干净"的排序目标**（smart/usage/pace/drain/expiring）：目标函数与毛利/质量约束方向相反。
- **自动汇率**：估值用 FX 必须是不可变版本、保守取整、失败关闭。
- **Agent 接线、Library、Skill/MCP router、Memory、Artifacts、同步备份**：单用户本机工具形态，服务端多租户网关不需要。

## aigate 自身的现存缺口（与 magpie 无关，对照时发现）

| 缺口 | 现状 | 性质 |
| --- | --- | --- |
| 裸 5xx 一律计渠道故障 | 被上游固定拒绝的请求可能误触发熔断 | 真实缺口，见 A1 |
| 429 冷却作用域是 `channel:model` | 池内一个 key 被限流会冷却整个渠道 | 真实缺口，见 A2 |
| 上游传输层每个请求重新拨号 | `DisableKeepAlives: true` | **有意取舍，非缺口**：为每次请求重做 DNS 校验与出口判定（防重绑定）。已列为待立项性能项，见 `docs/verification/performance-audit.md:64` |
| 渠道级 RPM | LLD 写了分层 RPM，但 `internal/routing` 与 `internal/catalog` 中未找到实现 | 待核实 |
| 空 200 回复 / 工具循环检测 | 未发现相关逻辑 | 待核实（未逐行核实流式"200、stop、无内容"如何结算） |

## 研究边界

- **未运行 magpie**。厂商词表覆盖面、各家冷却时长等只在文档与注释里见到，未验证其测试是否仍成立。
- **未实际渲染界面**。上下文树图、舞台飞线、磨砂弹出层等的效果由代码与仓库内截图推断；截图显示的是顶部标签布局，当前代码在 ≥1024px 默认是左侧栏。
- **阅读覆盖**。magpie 前端约 5 MB，只精读了与题目相关的函数（估计不到 15%）；`LESSONS.md`（1916 行）只读了机制说明与部分条目；社区插件仓库不在本地 checkout。
- **aigate 侧"后端数据是否已存在"** 依据前端 TypeScript 类型定义推断，未核对 Go 后端是否已采集但未暴露。
- **上游漂移快**：magpie 由 agent 高频发版（单日可达 220 commits），本文引用仅在 `e66d872` 下成立。
- **aigate 证据等级**：032/033/018/012 等的"已支持"都是本地 mock + 029 验收，真实供应商资格与生产资格均未授予。
