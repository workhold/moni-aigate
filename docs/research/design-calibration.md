## 2. 纠正了哪些容易误读的结论

1. **New API有并发和事务保护，但不是处处同一合同。** 初始估算预扣、发送前足额补足、普通补扣允许欠费不同；最终分组倍率可变化。moni的“固定客户售价、收费封顶R、钱包不透支”是主动选择，不能写成直接继承。
2. **订阅requestId防重与完整事务原子性也不是同义词。** 所读退款外层状态事务内部调用会从全局DB另开事务；本轮不能证明其故障同成败。moni明确tx句柄贯穿所有资金helper。
3. **局部限流fail-closed不代表HTTP调用链如此。** Unkey实际Key验证caller在特定限流error时继续准入。moni为权限、资金、限流内部错误和遥测分别写失败策略。
4. **max_retries配置不一定控制全部网络尝试。** Bifrost回归测试记录底层客户端曾放大拨号次数；moni定义跨层总生成派发上限，并分开计拨号与供应商请求。
5. **有终止marker不等于usage最终可靠，有usage也不等于交付成功。** SSE/协议/写入/计量/客户收费分别建模，不用一个success/error布尔值裁决钱包。
6. **隐藏正常输出不覆盖所有隐私出口。** Agent Router正常trace隐藏、错误exception/status、公开错误和debug有不同路径；moni在采集前限制内容，并单独构造公共错误、观测和证据。
7. **Higress framer的1MiB是未完成尾部上限。** 它作为观察者可丢弃并重新同步；moni财务协议解析采用完整/未完整event上限，不能丢帧后继续声称账单完整。

这些是特定固定路径的观察及设计取舍，不是对上游整体可靠性、安全性或生产事故的判定。

## 3. 已同步到设计的12项校准

| 编号 | 设计变化 | 为什么需要 | 规格 / 验收 |
|---|---|---|---|
| C-01 | 每个售卖profile明确参数、工具、输入上界、输出约束与计费维度 | 协议兼容名称不能证明隐藏推理/工具费用可控；保守冻结也有客户体验成本 | FR-03/05/07；AC-41 |
| C-02 | 最终/临时/估算/缺失/冲突usage分开，零与缺失不同 | 不将累积快照相加，也不用估算代替最终账单 | FR-03/07/12；AC-42 |
| C-03 | 按协议、传输、本地交付、计量和收费政策形成矩阵 | 明确部分输出、客户取消、无输出失败和结算后网络失败 | FR-07/09；AC-44 |
| C-04 | T1.9先存最小终结证据与恢复任务，T2再裁决；恢复模式无输出未结算免收 | 防止已拿到usage却只留内存，也避免仅凭completed向已消失请求补收 | FR-09/12；AC-45 |
| C-05 | 明确同pgx.Tx、真实父行锁和永久唯一键 | Transaction外壳、ctx命名或锁不存在行都不足以证明原子性/防重 | NFR-01；AC-46/49 |
| C-06 | Gateway/SDK/HTTP/反向代理合计最多两次生成派发 | 隐式重放可能绕过上层重试预算 | FR-04；AC-47 |
| C-07 | SSE提交点区别TTFT，首次事件前不预发200/心跳 | headers/role/心跳也会提交HTTP响应，提交后不能改状态或重试 | FR-03/04/09；AC-43 |
| C-08 | 总deadline共享，进展/idle分开；真实资源退出后归还许可 | 持续心跳不能无限占连接，handler结束也不代表上游资源已释放 | NFR-03/04；AC-48 |
| C-09 | 健康动作按故障来源及作用域；半开中性结果不罚渠道 | 取消、参数错和本地拒绝不能污染供应商健康；熔断不代表可安全重放 | FR-04；AC-52 |
| C-10 | 主库READ COMMITTED父行冲突锁后再读取授权子表；明确依赖失败矩阵 | 空grant、旧快照、只读副本/SWR都可能绕过即时撤销目标 | FR-01/02/04；AC-49 |
| C-11 | 公共错误/观测/证据独立白名单，采集前不积累正文 | 最终隐藏属性不证明中间无内容留存，错误正文也可能带秘密 | NFR-02/07；AC-50 |
| C-12 | 供应商秘密轮换与主加密密钥轮换分开，保留备份所需材料 | 不能拼旧endpoint与最新Key，也不能销毁旧备份的唯一解密材料 | FR-04，NFR-02/05；AC-51 |

全套仍为12项功能需求、7项非功能需求，验收从40个细化为52个场景，全部待执行。首版运行依赖仍为Go应用+PostgreSQL及外部密钥材料；没有为研究结果新增Redis/Kafka/Envoy/第三方计费服务。

## 5. 需要开发者审阅的政策与边界

- **首发范围**：邀请+人工核款，还是将自助支付/指定客户端协议前移？当前提案未因本轮研究自动获批。
- **收费矩阵**：length/tool_calls、业务拒绝、部分输出和客户取消在最终量可信时收费；计费责任点前无输出平台/上游失败免收；T2后网络失败保留收费并走争议退款。
- **恢复与截止**：已存证据也不延长24h资金截止；恢复模式未结算且明确无输出免收，部分输出/不明交付按证据处理。不能承诺扣款与网络交付原子化。

设计入口：[融合导读](../design/overview.md)、[HLD](../design/HLD.md)、[LLD](../design/LLD.md)、[spec](../../specs/001-commercial-mvp/spec.md)、[验收](../../specs/001-commercial-mvp/acceptance.md)。批准具体边界后再进入SDD实现；本轮未执行这些验收。
